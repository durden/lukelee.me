# Shortcomings of Git's abstractions and UI
[This article](https://steveko.wordpress.com/2012/02/24/10-things-i-hate-about-git/) does a great job of explaining some of the reasons why [Git](http://git-scm.com/) can be so confusing and frustrating for new (and old) users.

I have to agree with most of the complaints.  However, the positive spin on this is to think of how great of a job [Github](http://github.com) has done to [explode](http://www.forbes.com/sites/tomiogeron/2012/07/09/cash-for-code-github-raises-100-million-from-andreessen-horowitz/) the usage of  [Git](http://git-scm.com/) and help all of us put up with the shortcomings.

I can personally say I would never have kept using  [Git](http://git-scm.com/) if it wasn't for [Github's](http://github.com) great web interface and community.  In fact, since I'm a [Python](http://python.org) guy at heart I would probably be using [Mercurial](http://mercurial.selenic.com/) if I didn't discover [Github](http://github.com) first.

However, even though [Mercurial](http://mercurial.selenic.com/) is written in  [Python](http://python.org) I have spent a ton of time learning [Git](http://git-scm.com/) so I'm sticking with it for now.

So, if your new to [Git](http://git-scm.com/) and find it frustrating, try to stick with it or try out [Mercurial](http://mercurial.selenic.com/).  The [Distributed VCS](http://en.wikipedia.org/wiki/Distributed_revision_control) is the future.  So you'll likely need to know one of them.
