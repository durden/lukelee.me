# Programming Idioms
The always insightful [Zed Shaw](http://zedshaw.com) has a great article on [programming idioms](http://learncodethehardway.org/blog/AUG_19_2012.html).

> I might even go so far as to say programming languages don't have idioms at all. By definition an idiom is something you remove from good clean writing. Since these coding forms are more like social mores and expected of good clean code, they just can't be idioms.

The article is a great read.  It specifically discusses [Ruby](http://www.ruby-lang.org), but the same issues exist in the [Python](http://python.org) community.  [Python](http://python.org) features like [list comprehensions](http://docs.python.org/tutorial/datastructures.html#list-comprehensions) and [xrange](http://docs.python.org/library/functions.html#xrange) are good examples of **idioms** or **social mores** as [Zed](http://zedshaw.com) claims.  I know I have a bad habit of seeing code not using these (especially [xrange](http://docs.python.org/library/functions.html#xrange)) as a sign of a [Python](http://python.org) newcomer.
